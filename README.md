# workflow-history-go

本地工作流执行历史与回放服务。为每个工作流实例记录**状态迁移事件**、
**变量快照**与**逻辑时间**，支持按逻辑时间做时间点查询、从检查点确定性
回放、按保留策略压缩回收历史，并在崩溃后从最近一次已提交检查点恢复。

```
go test ./... -race
```

## 快速开始

```go
s, _ := history.Open(dir, history.Options{SegmentSize: 64})
defer s.Close()

// 追加状态迁移（不可变事件，全局唯一序号 + 实例内逻辑时间）
ev, _ := s.Commit("order-42", history.Transition{
    LogicalTime: 7,
    From:        "pending",
    To:          "paid",
    Vars:        map[string][]byte{"amount": []byte("100")},
})

// 时间点查询：只反映 t 之前已提交的完整状态
snap, _ := s.StateAt("order-42", 7)

// 检查点 + 从检查点确定性回放
ck, _ := s.CreateCheckpoint("order-42")
rs, _ := s.StartReplay("order-42", history.ReplayOptions{})
for {
    step, ok := rs.Next()
    if !ok { break }
    _ = step
}
_ = ck
```

## 一致性语义

**事件与序号**
- 每次状态迁移以不可变事件追加，携带全局单调递增且唯一的 `Seq`、
  实例内逻辑时间 `LogicalTime`、变量快照与墙钟时间。
- 写者在全局互斥锁上串行化，因此并发提交（包括同一实例）始终保持
  全局有序、序号不重复。
- 同一实例内逻辑时间必须**非递减**（同一逻辑时刻允许多次迁移）；
  违反者返回 `ErrNonMonotonicTime`。并发提交同一实例时，拿到过期
  逻辑时间的提交会被拒绝，调用方应取新的逻辑时间重试。

**已确认 = 已持久 = 可见**
- `Commit` 先写 WAL 并 fsync，再发布到内存视图；确认的事件必然可恢复。
- 崩溃恢复时，WAL 中校验失败或未写完的尾部记录被截断丢弃——
  **未完成的写入绝不会作为已确认状态出现**。
- 恢复顺序：最新检查点 → 清单引用的段文件 → WAL 中未封存的事件。
  已确认历史在重启后完整可见。

**读一致性**
- 每个实例的读视图是不可变结构，通过原子指针发布；读者**从不阻塞写者**，
  且总是看到一致的快照（状态名与变量快照来自同一事件）。
- `StateAt(t)` 返回逻辑时间 ≤ t 的最后一个已保留事件的状态，绝不混入
  更晚写入的内容。当 `Exact=false` 时，表示 t 早于最早已保留事件，
  返回的是最早已保留状态（压缩边界），见下文保留策略。
- 返回的 `Snapshot`/`Event` 均为深拷贝，调用方修改不会影响存储。

**回放语义**
- 回放从检查点（或恢复游标）开始，按全局序号顺序逐个投递已保留事件，
  状态随事件推进。**同一已保留历史 + 同一回放入口 ⇒ 结果完全一致**。
- 回放会话在启动时捕获历史的稳定快照，进行中的回放不受并发提交影响。
- 中断后用 `ReplayOptions{AfterSeq: session.Cursor()}` 重新开播即可续放，
  拼接结果与一次完整回放完全一致。
- 若续放游标本身已被回收，返回 `ErrHistoryReclaimed`。

## 保留策略

历史按**段**（segment）组织：实例的活动段写满 `SegmentSize` 个事件后
封存为不可变段文件，WAL 同步重写收缩。`RetentionPolicy`：

```go
history.RetentionPolicy{
    KeepSegments:   2,   // 最新的 2 个封存段永不压缩/回收
    ReclaimHorizon: 100, // 逻辑时间早于 (最新时刻-100) 的段可回收
    AutoMaintain:   true // 每次创建检查点后自动执行 Maintain
}
```

两级处理，均以**检查点覆盖**为前提（段内最大序号 ≤ 最新检查点序号），
因此**尚未被检查点覆盖的最近事件永远不会丢失**：

1. **精确压缩（Compact）**：合并符合条件的段，同一逻辑时刻只保留最后
   一个事件。对所有 `Exact=true` 的时间点查询结果**零影响**。
2. **回收（Reclaim）**：整段丢弃逻辑时间 ≤ 界限的段，替换为一条
   `summary` 事件（携带被回收区间末尾的完整变量快照）。回收后：
   - 界限之后的时间点查询保持精确（`Exact=true`）；
   - 落入被回收区间的查询返回边界摘要状态（`Exact=false`）——
     这是保留策略明确取舍的近似语义；
   - 从最新检查点出发的回放**完全不受影响**（回收只触及检查点覆盖的
     前缀），回放结果与回收前逐字节一致。

压缩/回收的崩溃安全：新段文件先持久化，再原子更新清单（tmp+rename），
最后删除旧文件；崩溃残留的孤儿文件在下次打开时自动清理。

## 持久化布局

> 同一数据目录同一时间只允许一个 `Service` 实例打开（单写者进程模型）；
> 崩溃后直接重新 `Open` 即可恢复。


```
<dir>/
  wal.log                              # 已提交事件批次（magic|len|crc32|JSON）
  segments/<instance>/manifest.json    # 存活段文件清单（原子发布）
  segments/<instance>/*.seg            # 封存/压缩后的段文件（带 CRC）
  checkpoints/<instance>/<seq>.chk     # 检查点（原子发布，保留最近 N 个）
```

## 测试覆盖

- `history_test.go`：序号单调唯一、逻辑时间约束、时间点查询、历史范围、
  检查点生命周期与修剪、返回值隔离性。
- `concurrency_test.go`（`-race`）：多实例并行写入、同实例并发提交、
  读写并发一致性、检查点与提交并发。
- `recovery_test.go`：崩溃后已确认历史完整可见、序号不复用、撕裂尾部
  截断、未确认写入不可见、压缩回收后再恢复。
- `compact_test.go`：精确压缩不改变查询结果、无检查点不可压缩、
  未覆盖事件不丢失、边界摘要、KeepSegments、自动 Maintain。
- `replay_test.go`：回放确定性、中断续放、指定检查点回放、压缩后回放
  不变、进行中回放不受并发写影响。
